# i18n and formatting: languages, money, dates, Vietnamese text

Correct money, times and names in a Vietnamese-first SaaS, ready for English and a branch abroad. Ran on Node 22.22 (ICU 77.1), intl-messageformat 12.1, next-intl 4.14 + Next.js 16.4, PostgreSQL 16 (FORCE RLS) and Chromium 153; removing any one of 13 safeguards made a test fail.

**Right-size it.** Vietnamese-only: sections 2, 3 and 5; UI strings may stay inline (no catalogs). Extracting them later stays cheap only if every amount and date goes through `format.ts`.

## 1. Choosing a tool

| Need | Use | Notes |
|---|---|---|
| Money, numbers, dates | built-in `Intl` behind one module | `Temporal`: Chromium 153 has it, Node 22 only behind `--harmony-temporal` (experimental): don't use yet |
| Messages, Next.js App Router | next-intl 4 | ICU syntax, typed keys (section 4) |
| Messages, React SPA | i18next 26 + react-i18next 17 + i18next-icu 2.6 | i18next's own syntax is `{{name}}` + `_one`/`_other` keys; i18next-icu reads ICU catalogs |
| Messages, Expo | i18next + expo-localization 58 | `getLocales()[0].languageCode` as first-run default only; tenant zone, not `getCalendars()[0].timeZone` |
| SMS, email, PDF | intl-messageformat 12 | Same catalogs (section 6) |

## 2. One formatting module

```ts
// src/i18n/format.ts — the ONLY place that formats money and dates (web, API, SMS, email, PDF)
export const LOCALES = ['vi', 'en'] as const;
export type Locale = (typeof LOCALES)[number];
// Always passed in, from user/customer + tenant settings; never read from the machine
export interface I18nContext { locale: Locale; timeZone: string } // IANA zone, e.g. 'Asia/Ho_Chi_Minh'

// ISO 4217 minor units; the currency comes with the price, never from the locale
const MINOR_UNITS = { VND: 0, USD: 2 } as const;
export type Currency = keyof typeof MINOR_UNITS;
export interface Money { amount: number; currency: Currency } // integer, smallest unit (đồng, cent)

// Node 22: new Intl.DateTimeFormat ≈ 70 µs, reusing one ≈ 2 µs
const cache = new Map<string, Intl.NumberFormat | Intl.DateTimeFormat>();
function cached<T extends Intl.NumberFormat | Intl.DateTimeFormat>(key: string, make: () => T): T {
  let f = cache.get(key);
  if (!f) cache.set(key, (f = make()));
  return f as T;
}

export function formatMoney(m: Money, locale: Locale): string {
  // Intl prints 999.5 as "1.000 ₫" silently: a fraction is a bug upstream
  if (!Number.isSafeInteger(m.amount)) throw new RangeError(`Money.amount must be an integer: ${m.amount}`);
  const d = MINOR_UNITS[m.currency];
  return cached(`money|${locale}|${m.currency}`, () => new Intl.NumberFormat(locale,
    { style: 'currency', currency: m.currency, minimumFractionDigits: d, maximumFractionDigits: d })).format(m.amount / 10 ** d);
}

// "1.250.000", "1,250,000", "1 250 000", "1250000đ" → 1250000; "1,25tr", "500k", "1,5" → null (ask again, never guess)
export function parseVndInput(input: string): number | null {
  const s = input.normalize('NFC').trim().replace(/\s*(₫|đ|vnđ|vnd)$/iu, '');
  if (!/^(?:\d+|\d{1,3}([., ])\d{3}(?:\1\d{3})*)$/u.test(s)) return null;
  const n = Number(s.replace(/\D/g, ''));
  return Number.isSafeInteger(n) ? n : null;
}

// vi "15:30 24/10/2026" (dateStyle 'short' gives a 2-digit year); en "Oct 24, 2026, 3:30 PM" (no 10/24 vs 24/10 doubt)
const DATE_TIME: Record<Locale, Intl.DateTimeFormatOptions> = {
  vi: { day: '2-digit', month: '2-digit', year: 'numeric', hour: '2-digit', minute: '2-digit' },
  en: { dateStyle: 'medium', timeStyle: 'short' },
};

// An instant (timestamptz). Without timeZone, Intl uses the machine's zone (server: UTC, browser: anything)
export function formatDateTime(at: Date, ctx: I18nContext): string {
  return cached(`dt|${ctx.locale}|${ctx.timeZone}`, () =>
    new Intl.DateTimeFormat(ctx.locale, { ...DATE_TIME[ctx.locale], timeZone: ctx.timeZone })).format(at);
}

// A calendar date (SQL `date`, 'YYYY-MM-DD' in the API: birthdays) has no zone, so format it in UTC
export function formatDateOnly(isoDate: string, locale: Locale): string {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(isoDate)) throw new RangeError(`Expected YYYY-MM-DD: ${isoDate}`);
  const { hour, minute, timeStyle, ...dateOnly } = DATE_TIME[locale];
  return cached(`d|${locale}`, () => new Intl.DateTimeFormat(locale, { ...dateOnly, timeZone: 'UTC' }))
    .format(new Date(`${isoDate}T00:00:00Z`));
}

// 'YYYY-MM-DD' of an instant in a zone (en-CA formats ISO-style), e.g. "today" for the tenant
export const localDate = (at: Date, timeZone: string): string =>
  cached(`iso|${timeZone}`, () => new Intl.DateTimeFormat('en-CA', { timeZone, dateStyle: 'short' })).format(at);
```

- `1.250.000 ₫` has a **no-break space U+00A0** before `₫` (Node 22 and Chromium 153): tests write `'\u00a0'`, a typed space fails. Never compare or parse formatted strings in logic.
- VND is integer đồng: `bigint` + currency code (the `vibe-backend` skill, `references/data-layer.md`); API `{ "amount": 1250000, "currency": "VND" }`.
- Currency comes from the price or tenant, not the locale (English UI: `₫1,250,000`).
- Pin Node in CI: exact strings depend on its ICU.

## 3. Time zones and dates in the database

| Value | Store | Show |
|---|---|---|
| Instant (appointment) | `timestamptz` (UTC) | `formatDateTime` with the tenant zone |
| Calendar date (birthday) | `date`; `'YYYY-MM-DD'` in the API | `formatDateOnly` |
| "Today", "this month" | computed in SQL, tenant zone | — |

```sql
-- Tenant settings; move time_zone/currency to branches when one opens abroad
CREATE TABLE tenants (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name           text NOT NULL,
  default_locale text NOT NULL DEFAULT 'vi' CHECK (default_locale IN ('vi', 'en')),
  -- IANA Area/City only: Postgres also accepts 'GMT+7', '+07' and 'Etc/GMT+7', and reads all three as UTC-7 (POSIX sign)
  time_zone      text NOT NULL DEFAULT 'Asia/Ho_Chi_Minh'
                 CHECK (time_zone ~ '^(Africa|America|Antarctica|Arctic|Asia|Atlantic|Australia|Europe|Indian|Pacific)/[A-Za-z0-9_/+-]+$'
                        AND now() AT TIME ZONE time_zone IS NOT NULL),
  currency       char(3) NOT NULL DEFAULT 'VND'
);
ALTER TABLE users ADD COLUMN locale text CHECK (locale IN ('vi', 'en'));  -- NULL: follow the tenant

CREATE TABLE customers (
  tenant_id uuid NOT NULL DEFAULT app_current_tenant() REFERENCES tenants (id),
  id        uuid NOT NULL DEFAULT gen_random_uuid(),
  full_name text NOT NULL CHECK (full_name IS NFC NORMALIZED),  -- one field, as typed
  birthday  date,                                               -- a calendar date, not a timestamp
  locale    text CHECK (locale IN ('vi', 'en')),                -- language of SMS/email to this customer
  PRIMARY KEY (tenant_id, id)
);
CREATE INDEX customers_name_vi ON customers (tenant_id, full_name COLLATE "vi-x-icu");
```

```ts
// src/appointments/by-day.ts — inside withTenant; day: 'YYYY-MM-DD' picked in the UI, or null for "today"
import type { PoolClient } from 'pg';

// Bounds = local midnights in the tenant zone (DST-safe). Scalar subqueries keep index (tenant_id, starts_at)
// in use; a join on tenants gave a seq scan (~55 ms vs ~0.3 ms on 200k rows).
export async function appointmentsOnDay(db: PoolClient, day: string | null) {
  const { rows } = await db.query<{ id: string; starts_at: Date }>(
    `WITH t AS (
       SELECT time_zone AS tz, COALESCE($1::date, (now() AT TIME ZONE time_zone)::date) AS d
         FROM tenants WHERE id = app_current_tenant()
     )
     SELECT id, starts_at FROM appointments
      WHERE starts_at >= (SELECT d::timestamp AT TIME ZONE tz FROM t)
        AND starts_at <  (SELECT (d + 1)::timestamp AT TIME ZONE tz FROM t)
      ORDER BY starts_at`,
    [day],
  );
  return rows;
}
```

- `Asia/Ho_Chi_Minh` is UTC+7, no DST: the day runs 17:00 to 17:00 UTC. `starts_at::date = '2026-10-24'` uses the session zone (often UTC): wrong rows (tested).
- Zone picker: options come from `pg_timezone_names`, so every choice is one the database accepts. Not from `Intl.supportedValuesOf('timeZone')`: Node 22 and Chromium 153 list Vietnam as `Asia/Saigon`, which this PostgreSQL 16 (Ubuntu tzdata) rejects. Preselect the browser's zone through `suggestTimeZone`; never store it unmapped.

```ts
// src/i18n/time-zones.ts — options for the tenant time zone picker, from the database that stores the value
import type { Pool, PoolClient } from 'pg';

// Same pattern as the tenants.time_zone CHECK: Area/City only. Drops Etc/GMT+7 (= UTC-7), UTC, EST5EDT, posixrules
export const ZONE_NAME = '^(Africa|America|Antarctica|Arctic|Asia|Atlantic|Australia|Europe|Indian|Pacific)/[A-Za-z0-9_/+-]+$';

export async function listTimeZones(db: Pool | PoolClient): Promise<string[]> {
  const { rows } = await db.query<{ name: string }>(
    'SELECT name FROM pg_timezone_names WHERE name ~ $1 ORDER BY name', [ZONE_NAME]);
  return rows.map((r) => r.name);
}

// ICU (Node 22, Chromium 153) reports these old names, e.g. Intl...resolvedOptions().timeZone === 'Asia/Saigon';
// PostgreSQL with system tzdata knows only the current ones. Every Intl.supportedValuesOf('timeZone') entry
// missing from pg_timezone_names on Ubuntu 24.04 is listed (tested).
const ICU_TO_IANA: Record<string, string> = {
  'Africa/Asmera': 'Africa/Asmara', 'America/Buenos_Aires': 'America/Argentina/Buenos_Aires',
  'America/Catamarca': 'America/Argentina/Catamarca', 'America/Cordoba': 'America/Argentina/Cordoba',
  'America/Godthab': 'America/Nuuk', 'America/Indianapolis': 'America/Indiana/Indianapolis',
  'America/Jujuy': 'America/Argentina/Jujuy', 'America/Louisville': 'America/Kentucky/Louisville',
  'America/Mendoza': 'America/Argentina/Mendoza', 'Asia/Calcutta': 'Asia/Kolkata', 'Asia/Katmandu': 'Asia/Kathmandu',
  'Asia/Rangoon': 'Asia/Yangon', 'Asia/Saigon': 'Asia/Ho_Chi_Minh', 'Atlantic/Faeroe': 'Atlantic/Faroe',
  'Europe/Kiev': 'Europe/Kyiv', 'Pacific/Enderbury': 'Pacific/Kanton', 'Pacific/Ponape': 'Pacific/Pohnpei',
  'Pacific/Truk': 'Pacific/Chuuk',
};

// Preselect the browser's zone in the picker; null when the list doesn't have it (the user picks)
export function suggestTimeZone(browserZone: string, options: readonly string[]): string | null {
  const name = ICU_TO_IANA[browserZone] ?? browserZone;
  return options.includes(name) ? name : null;
}
```

- `withTenant`: the `vibe-backend` skill (`references/postgres-rls.md`). node-postgres turns `date` into a `Date` at the server's local midnight (a day off once serialized) and `bigint` into a string. At startup: `pg.types.setTypeParser(pg.types.builtins.DATE, (v) => v)`; parse `INT8` to a safe integer.

## 4. Messages and locale choice

```json
{
  "appointments": {
    "todayCount": "{count, plural, =0 {Hôm nay chưa có lịch hẹn} other {Hôm nay có # lịch hẹn}}",
    "reminderSms": "Chào {name}, nhắc lịch hẹn của bạn lúc {when} tại {spa}."
  },
  "customers": {
    "count": "{count, plural, other {# khách}}"
  }
}
```

```json
{
  "appointments": {
    "todayCount": "{count, plural, =0 {No appointments today} one {# appointment today} other {# appointments today}}",
    "reminderSms": "Hi {name}, reminder: your appointment at {spa} is on {when}."
  },
  "customers": {
    "count": "{count, plural, one {# customer} other {# customers}}"
  }
}
```

- Keys by meaning, one file per locale, `vi.json` the source. Whole sentences, never `t('a') + name + t('b')`.
- Plurals follow `Intl.PluralRules`: vi has only `other`, en `one`/`other`. `=0` works in both.
- Staff locale: `users.locale` > tenant default > `Accept-Language` > `vi` (`resolveLocale`). Customer messages: `customers.locale` > tenant default. Locale in the URL (`/en/...`) only on public pages; SEO: the `vibe-frontend` skill (`references/seo.md`).

```ts
// src/i18n/request.ts — next-intl 4, Next.js App Router staff app (no locale in the URL)
import { getRequestConfig } from 'next-intl/server';
import { headers } from 'next/headers';
import { getViewer } from '../server/viewer'; // yours: session user + settings of the tenant in the URL
import { resolveLocale } from './locale';
import { messagesFor } from './messages';

export default getRequestConfig(async () => {
  const viewer = await getViewer();
  const acceptLanguage = (await headers()).get('accept-language');
  const locale = resolveLocale({ user: viewer.userLocale, tenant: viewer.tenantLocale, acceptLanguage });
  // Server and browser render with this zone and clock
  return { locale, timeZone: viewer.timeZone, now: new Date(), messages: messagesFor(locale) };
});
```

- `NextIntlClientProvider` in the root layout hands locale, messages, `timeZone` and `now` to client components, which call `formatDateTime` with `useLocale()` and `useTimeZone()`. Declare `AppConfig` (`Locale`, `Messages`): `t('cuont')` then fails to compile.
- **Hydration:** `toLocaleString('vi-VN')` without `timeZone` rendered `08:30:00` on a UTC server, `15:30:00` in a Vietnamese browser: React error #418 (tested). `suppressHydrationWarning` only hides it. Without `timeZone` in `request.ts`, next-intl hands the server's zone (UTC) to the browser: no mismatch, `08:30` everywhere.

CI check, `npm run check:messages`:

```ts
// src/i18n/check-messages.ts — CI step: node --import tsx src/i18n/check-messages.ts messages
// Each locale: exactly vi's keys, the same {arguments}, plural branches per Intl.PluralRules
import { isPluralElement, isStructurallySame, parse, type MessageFormatElement } from '@formatjs/icu-messageformat-parser';
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';
import { fileURLToPath } from 'node:url';

function flatten(node: object, prefix = '', out = new Map<string, string>()): Map<string, string> {
  for (const [k, v] of Object.entries(node)) {
    if (typeof v === 'string') out.set(prefix + k, v);
    else flatten(v, `${prefix}${k}.`, out);
  }
  return out;
}

// en needs one + other; vi has only other (`one` in vi is dead text); =0 branches are always fine
function pluralErrors(ast: MessageFormatElement[], locale: string): string[] {
  const allowed: string[] = new Intl.PluralRules(locale).resolvedOptions().pluralCategories;
  return ast.filter(isPluralElement).flatMap((el) => {
    const keys = Object.keys(el.options).filter((k) => !k.startsWith('='));
    return [
      ...allowed.filter((c) => !keys.includes(c)).map((c) => `{${el.value}} lacks '${c}'`),
      ...keys.filter((k) => !allowed.includes(k)).map((k) => `{${el.value}} has '${k}', not a ${locale} category`),
      ...Object.values(el.options).flatMap((o) => pluralErrors(o.value, locale)),
    ];
  });
}

export function checkMessages(dir: string, base = 'vi'): string[] {
  const load = (locale: string) => flatten(JSON.parse(readFileSync(join(dir, `${locale}.json`), 'utf8')));
  const ref = load(base);
  const errors: string[] = [];
  for (const locale of readdirSync(dir).filter((f) => f.endsWith('.json')).map((f) => f.slice(0, -5))) {
    const catalog = load(locale);
    for (const key of ref.keys()) if (!catalog.has(key)) errors.push(`${locale}: missing ${key}`);
    for (const [key, message] of catalog) {
      const refMessage = ref.get(key);
      if (refMessage === undefined) { errors.push(`${locale}: ${key} is not in ${base}.json`); continue; }
      try {
        const ast = parse(message, { requiresOtherClause: true });
        const same = isStructurallySame(parse(refMessage), ast);
        if (!same.success) errors.push(`${locale}: ${key}: ${same.error?.message}`);
        errors.push(...pluralErrors(ast, locale).map((e) => `${locale}: ${key}: ${e}`));
      } catch (err) {
        errors.push(`${locale}: ${key}: invalid ICU message (${(err as Error).message})`);
      }
    }
  }
  return errors;
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  const errors = checkMessages(process.argv[2] ?? 'messages');
  errors.forEach((e) => console.error(e));
  process.exitCode = errors.length ? 1 : 0;
}
```

## 5. Vietnamese text

```ts
// src/i18n/text.ts — Vietnamese text helpers
// All free-text input: NFC (NFD looks identical but compares unequal), trimmed, single spaces
export const cleanText = (s: string): string => s.normalize('NFC').trim().replace(/\s+/gu, ' ');

// Anh, Ánh, Ăn, Âu, Bình, Dương, Đặng; plain sort() is UTF-16 order (Á, Đ after Z)
export const compareVi = new Intl.Collator('vi').compare;

// For SMS without diacritics. NFD + strip marks leaves đ/Đ (separate letters), so map them explicitly.
export const removeDiacritics = (s: string): string =>
  s.normalize('NFD').replace(/\p{M}/gu, '').replace(/đ/g, 'd').replace(/Đ/g, 'D');
```

- Root `localeCompare()` is wrong too (`Ăn` first, `Đặng` before `Dương`).
- PostgreSQL: this cluster defaults to `C.UTF-8` (byte order). `ORDER BY full_name COLLATE "vi-x-icu"` matches `compareVi` (check: `SELECT collname FROM pg_collation WHERE collname LIKE 'vi%'`). `REINDEX` ICU-collated indexes after an OS ICU upgrade.
- `'Nguyễn'.normalize('NFD')` is 8 UTF-16 units, not 6: `!==`, `includes` fails. `CHECK (full_name IS NFC NORMALIZED)` catches what skips `cleanText`.
- Case mapping is safe. Keep `full_name` as typed (family name first); don't split it.

## 6. Server-side text: SMS, email, PDF

```ts
// src/i18n/messages.ts — catalogs with vi fallback; t() for SMS, email, PDF
import { IntlMessageFormat } from 'intl-messageformat';
import en from '../../messages/en.json' with { type: 'json' };
import vi from '../../messages/vi.json' with { type: 'json' };
import type { Locale } from './format';

export type Catalog = { [key: string]: string | Catalog };
export type Messages = typeof vi;

// A key missing in en shows the vi text (CI should catch it first)
export function withFallback(base: Catalog, over: Catalog): Catalog {
  const out: Catalog = { ...base };
  for (const [k, v] of Object.entries(over)) {
    const b = out[k];
    out[k] = typeof v === 'object' && typeof b === 'object' ? withFallback(b, v) : v;
  }
  return out;
}
const CATALOGS: Record<Locale, Messages> = { vi, en: withFallback(vi, en) as Messages };
export const messagesFor = (locale: Locale): Messages => CATALOGS[locale];

// Money and dates arrive formatted by format.ts: {at, date} in a message uses the machine's zone
export function getTranslator(locale: Locale) {
  return (key: string, values?: Record<string, string | number>): string => {
    let node: string | Catalog | undefined = CATALOGS[locale];
    for (const part of key.split('.')) node = typeof node === 'object' ? node[part] : undefined;
    if (typeof node !== 'string') throw new Error(`Unknown message key: ${key}`);
    return String(new IntlMessageFormat(node, locale).format(values));
  };
}
```

```ts
// src/notify/reminder-text.ts
import { formatDateTime, type I18nContext } from '../i18n/format';
import { getTranslator } from '../i18n/messages';
import { removeDiacritics } from '../i18n/text';

// ctx = the CUSTOMER's language (customers.locale ?? tenants.default_locale) + the tenant's zone
export function reminderText(a: { customerName: string; spaName: string; startsAt: Date }, ctx: I18nContext, opts: { ascii: boolean }) {
  const text = getTranslator(ctx.locale)('appointments.reminderSms',
    { name: a.customerName, spa: a.spaName, when: formatDateTime(a.startsAt, ctx) });
  return opts.ascii ? removeDiacritics(text) : text;
}
```

- The reminder job in the `vibe-backend` skill (`references/jobs.md`) formats with `formatDateTime` in the tenant's zone and sends unaccented Vietnamese (`removeDiacritics`). Once customers read other languages, switch it to `reminderText`: customer's language, tenant's zone, never the worker's.
- `ascii: true` → `Chao Dang Thi Anh, nhac lich hen cua ban luc 15:30 24/10/2026 tai Spa Hoa Mai.` Use it when the SMS provider or brandname template requires unaccented text.

## 7. Rules

1. One module formats money and dates everywhere, with explicit locale and time zone.
2. Money is integer minor units + currency; never guess when parsing input.
3. Instants `timestamptz`, calendar dates `date`; day boundaries in SQL, tenant (later branch) zone.
4. IANA Area/City zone names only: PostgreSQL reads `'GMT+7'`, `'+07'` and `'Etc/GMT+7'` as UTC−7.
5. Whole sentences, keys by meaning; CI fails on key, argument or plural mismatches.
6. NFC input; Vietnamese collation.

## 8. Tests

`node --import tsx --test --test-concurrency=1 test/*.test.ts` (30 tests, real DB as `app_user`); after `next build`, `test-web/hydration.test.ts` (3 tests, Chromium).

| Area | Asserts |
|---|---|
| Money | `'1.250.000\u00a0₫'` ≠ `'1.250.000 ₫'`; `999.5` throws; `1,25tr` → `null` |
| Dates | `'15:30 24/10/2026'` under any `TZ`; `17:00:00Z` → next day; SQL day `[23T17:00Z, 24T17:00Z)`; DST day 25 h |
| Zones | CHECK rejects `GMT+7`, `Etc/GMT+7`, `UTC`; accepts every picker option; every ICU `Area/City` zone maps to an option |
| Catalogs | missing/extra key, `{nmae}`, en without `one`, vi with `one`, broken ICU: exit 1 |
| Text | `vi-x-icu` = `compareVi`; NFD rejected; `Đặng` → `Dang` |
| Hydration | UTC server, New York/Hanoi browsers: same text; naive page: #418 |
